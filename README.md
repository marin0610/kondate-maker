# 献立メーカー

近所のお店の特売と冷蔵庫の在庫から、「安くて大量に作れる献立」を提案するWebアプリです。ブラウザで開くだけで動き、データはその端末のブラウザ内（localStorage）に保存されます。

## 概要（第2版）

- 対象は、主婦層と一人暮らしで自炊する人です。すべての献立に「1食あたりの単価」が出るのが特長です。
- 画面は「献立提案／レシピ／お店・特売／冷蔵庫／設定」のタブ構成です。
- 献立提案では、冷蔵庫の在庫だけで作れる献立（在庫で作れる）と、特売や買い足し少しで作れる献立（あと少しで作れる）を並べます。
- 献立を開くと、材料ごとの状態（在庫あり／特売あり／買い足し）と概算コスト、作り方、買い物リスト（不足食材と、特売価格があればその価格での概算、合計目安）が見られます。「2倍の量（作り置き）」への切り替えもできます。
- レシピはアプリ内蔵データのみです（現在79件）。他サイトの文章や写真の転載はしていません。分量と手順は自前の言葉で書いています。収録基準は「安い・大量・鍋ひとつ又はフライパンで作れる・味は濃いめ」が中心で、カレー、うどん、鍋、丼、炒め物、麺、煮物、汁物、副菜、主食、レンジのみ、揚げ物のレシピまで広げました。韓国料理（プルコギ／ビビンバ／チヂミ／キムチチゲ）・中華料理（青椒肉絲／エビチリ／中華丼／担々麺／八宝菜）・タイ風（ガパオライス／トムヤム風うどん）・ベトナム料理（鶏フォー／生春巻き／バインミー風サンド）などの海外の人気料理も収録しています。とんかつ、ハンバーグ、オムライス、ナポリタン、カルボナーラなどの定番人気メニューも厚くしています。食材の制限は設けていません（小松菜やパクチーも使います。苦手な食材は使う側が除外設定できます。下記参照）。
- 足りないときのために、材料・特売メモ・在庫の各行に「レシピを探す」リンクがあり、クックパッド検索へ飛ぶだけの形にしています（レシピ自体の取り込みはしません）。
- 本体は `index.html` の1ファイルで完結します（お店の検索のときだけ、OpenStreetMap系の無料APIに通信します）。

### カロリー目安

- 各レシピに1食あたりのカロリー目安（kcal）を付け、カードと詳細に表示します。
- **この数値は材料の量からの推定値です**（実測値ではありません）。 `#ガッツリ`（目安650kcal以上）／ `#ヘルシー`（目安500kcal以下で野菜・豆腐・魚中心）の判定根拠にも使っています。

### 表示順の切り替え

- レシピ一覧と献立提案の両方で、表示順をセレクトで切り替えられます：おすすめ順／安い順（1食単価）／カロリー高い順／カロリー低い順／時短順／食分数が多い順。
- おすすめ順は「作りやすさ（不足材料の少なさ）→ 1食単価」の順です。

### 苦手な食材の除外（NG食材）

- 「設定」タブで苦手な食材を登録・保存できます（localStorageに保存され、バックアップにも含まれます）。
- 登録した食材を含むレシピは、献立提案から自動で除外されます（除外件数が提案画面に表示されます）。
- レシピ一覧では「苦手な食材を含むレシピを除く」チェックで除外でき、外すと該当レシピに「苦手食材：○○」のバッジが付きます。詳細画面でも警告が出ます。

### アレルギーの登録と常時除外

- アレルギーは命に関わるため、苦手な食材（NG）とは別のリストで扱います。「設定」タブの「アレルギー（必ず除外）」で登録・削除でき、localStorageにNGとは別のキー（`allergy`）で保存され、バックアップにも含まれます。
- 登録した食材を含むレシピは、献立提案からもレシピ一覧からも**常時除外**されます（オフにするチェックはありません）。この除外はアプリ内で最優先（絶対）で、優先食材・在庫・特売・並び替えなど他の要素で上書きされることはありません。提案画面では「アレルギーで○件」「苦手で○件」と除外件数を分けて表示し、レシピ一覧でも「アレルギーで○件を除外中」と明示します。レシピ一覧の「優先食材のみで探す」モードでも表示されません（あのモードで赤文字警告付きで見えるのは、苦手な食材を含むレシピだけです。下記「優先食材のみで探す（警告付き表示）」参照）。
- 特定原材料8品目（卵・乳・小麦・そば・落花生・えび・かに・くるみ）は、チップをタップするだけで登録・解除できます。自由入力も可能です。
- 照合方法はNGと同じく材料名へのキーワード照合（部分一致）ですが、表記ゆれ対策として、8品目については関連語グループでも照合します。工夫した範囲は次のとおりです：卵＝たまご・玉子・マヨネーズ、乳＝牛乳・チーズ・バター・ヨーグルト・生クリーム・クリーム・ミルク・練乳、小麦＝小麦粉・薄力粉・強力粉・パン粉・パン・うどん・そうめん・パスタ・マカロニ・中華麺・焼きそば・餃子の皮・春巻きの皮・天ぷら粉、そば＝そば粉、落花生＝ピーナッツ・ピーナツ、えび＝エビ・海老、かに＝カニ・蟹・カニカマ・かにかま、くるみ＝クルミ・胡桃。登録語がグループの関連語（例：「牛乳」）でも、グループ全体で照合します。
- **正直な限界**：この照合は材料名ベースであり、完全な保証ではありません。調味料などに含まれる由来成分（例：醤油に含まれる小麦）、材料名から分からない加工品の成分、コンタミネーション（製造過程での混入）は判定できません。関連語の広げ方によっては、関係ないレシピを余分に除外することもあります。**アレルギー判定の最終確認は利用者自身が行い、作る前に材料と食品の原材料表示を必ず確認してください**（この注意書きはアプリ内の設定画面にも表示しています）。

### 優先したい食材

- 「設定」タブで、好きな食材や早く使い切りたい食材を「優先したい食材」として登録できます（苦手な食材と同じタグ形式：入力して追加・タップで削除。localStorageに保存され、バックアップにも含まれます）。
- 献立提案の「おすすめ順」では、優先食材を使うレシピが上位に出ます（優先食材のヒット数が多い順→不足材料の少なさ→1食単価）。レシピカードには「優先食材：○○」のバッジが付き、どの食材で優先されたか分かります。レシピ一覧でも同じバッジが出て、おすすめ順では同様に上位に出ます。
- **優先順位の原則：アレルギー（絶対）＞ 苦手 ＞ 優先食材**。アレルギー除外は最優先で絶対であり、優先食材ブースト・並び替え・冷蔵庫の在庫・特売など他のどの要素でも上書き・浮上させることはありません（除外は提案・一覧の生成前に適用されます）。除外対象のレシピは、優先食材を登録しても絶対に浮上しません。同じ材料が優先と苦手/アレルギーの両方に当てはまる場合は、除外が勝ち、その材料は優先としても数えません。
- **期限連動の自動優先**：冷蔵庫の在庫に賞味期限（任意）を登録すると、**期限切れ・あと3日以内**の食材は優先食材へ自動で合算されます。自動優先は在庫データから都度計算する方式で、在庫を削除すれば自動優先からも外れます。設定の「優先したい食材」欄の下に「期限が近いため自動で優先中」として対象食材と残り日数が表示され、レシピカードには「期限間近：○○（自動優先）」のバッジが付きます。提案画面の注記にも、自動優先中の在庫が表示されます。
- 優先順位は自動優先でも変わりません：**アレルギー（絶対）＞ 苦手 ＞ 優先食材（手動＋期限連動）**。期限が近くても、アレルギー/苦手に当てはまる材料は優先として数えず、除外対象のレシピが浮上することはありません。「優先食材のみで探す」モードの対象にも、期限連動の自動優先は含まれます。

### 優先食材のみで探す（レシピ一覧限定・苦手だけ警告付き表示）

- レシピ一覧の「優先食材のみで探す」をオンにすると、優先食材（手動登録リスト）を使うレシピだけが一覧に出ます。「優先食材で絞りたいけれど、苦手なものが混ざっていないか自分の目で確認したい」という使い方のためのモードです。
- このモードでの扱いは、苦手とアレルギーで明確に分けます：
  - **苦手食材を含むレシピ**：通常の除外で消してしまわず、表示したままにします。その代わり、赤文字で「苦手な食材：○○ を含みます」と明示し、カードの枠も赤系にして一目で分かるようにします。一覧の上部にも、苦手を含むレシピを赤文字で表示中である旨と件数を表示します。
  - **アレルギー食材を含むレシピ**：このモードでも**表示しません**。アレルギーは常時除外（絶対）を維持し、赤文字警告付き表示の対象からも外します。一覧の件数表示では「アレルギーで○件を除外中」と明示します。
- **線引き（重要）**：苦手の「見せる」扱いは、レシピ一覧の「優先食材のみ」モードでの表示だけです。**献立提案では従来どおりアレルギー絶対除外・苦手除外を維持し、このモードで見えているレシピが提案に出ることはありません**。通常のレシピ一覧（このモードがOFFのとき）も従来どおりで、アレルギーを含むレシピは常時非表示、苦手を含むレシピはチェックに応じて除外されます。
- 優先食材が未登録の状態でこのモードをオンにすると、一覧が空になるだけで終わらせず、「設定タブで優先したい食材を登録してください」という案内文を表示します。

## お店の登録（4つの方法）

1. **現在地から探す**：位置情報を使い、OpenStreetMapの無料データ（Overpass API）で半径1.5km以内のスーパー・ドラッグストア・百貨店/量販店・コンビニ・八百屋・薬局を近い順に表示します。タップで「いつものお店」に登録できます。
2. **店名・地名で検索（手打ち検索）**：Nominatimで「スーパー〇〇 ○○店」のように店名＋地名を検索し、結果から選んで登録できます。
3. **郵便番号から探す**：郵便番号（例：0123456）→住所（zipcloud）→座標（Nominatim）→近くの店（Overpass）の順に探します。引っ越した直後など、現在地が使いにくいときの予備導線です。
4. **手動登録**：店名を手で入力して登録します（ネットに載っていない個人店など向け）。

- 登録したお店には、チラシ掲載ページ（トクバイ等）のURLを任意で保存でき、一覧から直接開けます。
- チラシの価格データを自動取得する仕組みは入れていません。特売は「特売メモ」として手入力する形式です（写真OCRも入れていません）。

### 現在地検索（Overpass）の堅牢化（第2版）

- 本家 `overpass-api.de` は無料の公共サーバーのため、混雑時に容量オーバー（502等）で失敗することがあります（実機で報告あり）。
- 第2版では、エンドポイントを順に試すフォールバック（overpass-api.de → overpass.kumi.systems → overpass.nchc.org.tw）、AbortControllerによる20秒タイムアウト、本家の混雑系エラー（429/502/503/504）時の3秒待機＋1回リトライを実装しました。クエリも `timeout:20`・`out center 50` に軽量化しています。
- すべて失敗した場合は、画面に「地図サーバーが混雑している可能性があります」と表示し、店名検索・郵便番号検索への切り替えを案内します。
- **最終フォールバック（Nominatim viewbox検索）**：Overpassが全エンドポイント失敗した場合でも諦めず、Nominatimのviewbox検索（中心座標の±0.02度の範囲・bounded=1）でカテゴリ別に近隣のお店を探します。クエリは supermarket／convenience／chemist／greengrocer／pharmacy の5件のみを逐次実行し（利用ポリシーに配慮してリクエスト間隔を1秒以上空けます）、重複を除いて距離を計算し、近い順に最大50件（2.5km以内）を表示します。フォールバックで見つけた場合は、画面に「地図サーバーが混雑していたため、別の検索方法（Nominatim）で ○件見つかりました」と表示します。現在地検索・郵便番号検索のどちらでもこのフォールバックが働きます。

## 特売メモ

- 食材名と価格を入れる軽い形式です。価格の単位は「100gあたり」「1個あたり」「1パックあたり」などから選びます。お店も任意で紐づけられます。
- 献立の計算では、材料名が一致し単位換算ができる場合に、ふだんの価格の代わりに特売価格で計算します（例：鶏もも肉 100gあたり88円）。

## 冷蔵庫の在庫

- 食材名と量（目安の自由記入）を登録できます。在庫にある材料は献立提案で優先され、「在庫で作れる」判定に使われます。
- 賞味期限（任意・日付入力）も登録でき、在庫一覧でいつでも変更できます。在庫一覧では期限と残り日数（「あと○日」「今日まで」「期限切れ：○日過ぎ」）を表示し、期限切れは赤、3日以内は橙で目立たせます。一覧は期限が近い順に並びます（期限なしは最後）。期限切れ・3日以内の食材は、優先食材へ自動合算されます（上記「期限連動の自動優先」参照）。

## レシピと単価計算

- 各レシピは「材料（レシピ既定の分量）・ふだんの価格の目安・何食分か」をデータとして持っていて、合計コストと1食単価（合計÷食分、小数切り捨て）を計算します。
- 材料の状態は、在庫にあれば「在庫あり」、特売メモにあれば「特売あり」、どちらもなければ「買い足し」です。調味料などの細かい材料は「家にある前提」として、作れる判定には数えません。
- 価格はあくまで概算です。特売メモを入れると、その価格で再計算されます。

## 料理写真について（AI生成画像の方針）

- レシピデータには画像ファイル名の欄（`img`、例：`curry.jpg`）を持たせています。料理写真は、後からAIで生成した画像を同名ファイルで `index.html` と同じ場所に置いて差し込む方針です（他人の写真は使いません）。
- 画像ファイルがある場合はレシピカードと詳細画面に表示され、無い場合は絵文字と料理名のプレースホルダが表示されます。レシピ一覧が確定した後に、画像を別途生成します。

## データとバックアップ

- データ（お店・特売メモ・在庫・苦手な食材・アレルギー・優先したい食材）はブラウザの localStorage に保存されます。Safariのデータ消去などで消えることがあるため、「設定」タブからJSONで書き出し/読み込みができます。読み込みは今のデータを置き換えます（確認ダイアログあり）。
- バックアップ形式：現在は `{ app: "kondate-maker", version: 5, exportedAt, stores, sales, stock, ng, allergy, priority }` です（在庫アイテムは `expiry`＝賞味期限 YYYY-MM-DD を含みます）。第1版のバックアップ（`ng` なし）も、アレルギー追加前（`allergy` なし）・優先食材追加前（`priority` なし）・賞味期限追加前（在庫に `expiry` なし）のバックアップもそのまま読み込めます（無い項目は空として扱います）。過去の保存データ（localStorage）もそのまま引き継がれます。

## 検証について

- 構文チェック（JavaScript、`node --check`）を実施し、問題ありませんでした。
- 単価計算の単体確認（手計算との一致：例・大盛りチキンカレーは標準価格で合計1,213円・1食303円、鶏もも肉の特売88円/100gを入れると合計1,153円・1食288円）は、レシピ拡充（79件）後も壊れていないことを確認しています（アプリ本体の `evaluateRecipe` での再計算でも一致）。そのほか、全79件にkcal・タグ・材料・手順がありid・画像ファイル名の重複がないこと、タグ12種すべての付与件数（上記）と新タグ3種の判定基準への整合、タグ判定ルール（節約=1食220円以下／時短=15分以内／ガッツリ=650kcal以上／ヘルシー=500kcal以下）の全件整合、並び替え、NG除外（ピーマンを含むレシピは回鍋肉風キャベツ炒め・青椒肉絲・ガパオライス・ナポリタン・チャプチェ・焼きうどんの6件で、登録すると提案から外れること）の動作確認テストも全項目PASSでした。1食単価は全レシピで36円〜352円の範囲です。
- Nominatim viewboxフォールバックは、fetchをモックした単体テストで「Overpass全滅→Nominatimで取得→重複除去・近い順ソート・フォールバック表示文」の動作を確認しました（実データ取得は公開後の実機確認が望ましい項目です）。
- アレルギー機能の確認：アプリ本体の関数をNode.jsで読み込み、特定原材料8品目のプリセット登録→関連語での照合（例：「乳」登録で牛乳・チーズ・バター入りレシピがヒット、「卵」登録でマヨネーズ入りがヒット）→提案・一覧からの常時除外と件数の分離表示、バックアップの書き出し/読み込みに `allergy` が含まれること、アレルギー追加前の旧バックアップ（`allergy` なし）が読み込めることを確認しました。
- 優先食材の確認：同じくNode.js上で、優先食材を登録すると該当レシピが提案のおすすめ順で上位に来ること（優先なしの場合との比較）、カードに「優先食材：○○」バッジが出ること、優先食材と苦手/アレルギーが重なるレシピは除外が勝って提案に出ないこと、バックアップに `priority` が含まれることを確認しました。あわせて、アレルギーの絶対性として、対象食材を優先食材に登録し、在庫と特売も全材料分そろえた状態でも、対象レシピが献立提案とレシピ一覧のどちらにも出ないことを確認しました。
- 「優先食材のみで探す」モードの確認：優先食材＋苦手食材を含むレシピ（例：キャベツ優先・ピーマン苦手で回鍋肉風キャベツ炒め）が、赤文字警告「苦手な食材：ピーマン を含みます」付きで一覧に表示されること、アレルギー食材を含むレシピ（例：卵を優先・アレルギーの両方に登録した状態の鶏の照り焼き丼）はこのモードでも一覧に表示されず「アレルギーで○件を除外中」と明示されること、どちらのレシピも献立提案には出ないこと、優先食材が未登録のときは案内文が出ることを確認しました。
- 賞味期限・期限連動の自動優先の確認：在庫に賞味期限（3日以内）を登録すると自動優先の対象になり、該当レシピ（鶏もも肉の期限間近でチキンカレー）がおすすめ順で先頭に浮上し、カードに「期限間近：鶏もも肉（自動優先）」バッジが出ること、期限切れも同様に対象になること、10日先・期限なしは対象外であること、在庫一覧で残り日数と色分け（期限切れ＝赤、3日以内＝橙）と期限編集用の日付入力が出ること、設定の優先欄と提案ノートに自動優先中である旨が出ること、在庫を削除すると自動優先からも外れること、全材料を期限間近の在庫でそろえてもアレルギー対象レシピは提案に出ないこと、賞味期限追加前の保存データ（在庫に `expiry` なし）が読み込めることを確認しました。
- 店名検索（Nominatim）で実在のスーパーが見つかること、郵便番号検索（zipcloud）の応答は第1版で確認済みです。位置情報からの近隣検索（Overpass API）は第2版でフォールバック化しましたが、公共サーバーの混雑状況に依存するため、実データ取得の可否は時間帯により変わります（実機での再確認が望ましい項目です）。
